# Electron orbitals viewer project site design document
The site should have a very sharp, modern look, using a dark theme with orange and blue as accent colors. on the left side should be a collapsible menu. This menu should hold an interactive periodic table, and if I hover over an element, its square grows in size, and if I click on an element, that element should be selected. Please make the squares have sharp edges (not rounded) and add an ease transition when they grow or shrink in size, and please add some space in between each element's square so that they are not all squished together. color each element's square according to its chemical group/category on the periodic table.
When an element is not hovered over, its 1 or 2 letter symbol, atomic number, and full name should be displayed. When hovered over, its atomic mass should also be shown.
The full periodic table should only be shown when the left menu is expanded. When an element is selected, the left menu should collapse to the left, leaving the left column to only display the selected element in a big square (so the user knows which element they are observing). When that big element is clicked, the left menu should expand again and show the full periodic table, allowing the user to select another element.
The right side of the sight should be the 3d view of the electron orbitals using three.js. Make a 3d viewport window that displays the 3d view; an x-axis, y-axis, and z-axis should also be shown. When an element is selected, the 3d viewport should show a nucleus, plus all the orbitals that element has. the glb files of the orbitals can be used (i have converted the objs you've given me into glbs). As we talked about, I would like the orbitals to be transparent so we can see the ones on the inside. Opacity should be adjustable via a slider, though. An important thing; there should be a small menu to select which orbitals are visible, so the user can toggle visibility of certain orbitals to see them or reveal other orbitals inside. There should be a quick action button to hide all orbitals, show all orbitals, and a toggle for each energy level to hide/show all orbitals in an energy level at once. This is for the QoL of the user. you can lay it out like this: on the right side, the 3d viewport only takes up a good amount of space on the very right. left of the 3d viewport should be a rounded corner rectangular menu showing all the orbitals, organized by energy level. The orbitals within the energy level are grouped into rectangles within the menu, and each rectangle has its energy level labeled. there should be two buttons, show all and hide all, in the top of this menu. when an energy level label is clicked, the entire energy level should be hidden or shown. Whenever individual orbital buttons are clicked, that orbital's visibility is toggled. The visibility updates should be represented in real time on the 3d viewport. the user can drag while holding middle click to pan in the 3d viewport, drag while holding left click to orbit in the 3d viewport, and use the scroll wheel to zoom. There should be a small button in the top right corner of the 3d viewport that when clicked, returns the 3d viewport to its original top corner point of view (undoing the user's pans, rotations, and zooms).
Below the left/right blocks (so below the big square representing the selected element, the orbital visibility menu, and the 3d viewport), a PES diagram should be drawn for the selected element.
when the big square representing the selected element is clicked and the left block expands to show the entire periodic table, the orbital visibility menu should be hidden and the 3d viewport should get smaller to accommodate the periodic table, but the 3d viewport should still be there, so that means the periodic table, when expanded, should not take the full width of the page. because the PES diagram is beneath all this, it can take the full width of the page.
finally, add a "play" button somewhere which will animate the 3d view of the orbital; the animation should start with just the nucleus in the origin, and then slowly each orbital will fly into place, one at the time, starting from all the orbitals from the lowest energy levels and lowest ml values to the highest energy levels and highest ml values. Remember to scale orbitals of higher energy levels by x=1.75, as you suggested in another chat. The rule would be scale = 1.75^(n-1) power, where at the first energy level (n=1), the orbital models are scaled 1.0, and then energy levels after that multiply the scale by 1.75. because the orbitals get bigger, during animation, if the next energy level is reached, the 3d view should automatically slowly zoom out to show the s orbital of the next energy level before continuing the animation. there should be another button in the top left corner of the 3d viewport to toggle auto-spin, where the camera will automatically orbit around the orbitals to show them from all angles. the user can toggle this auto-spin button while the play animation is playing to get a 360 view, but the user should not be able to zoom, pan, or rotate the 3d view until the animation is complete. When the play button is clicked, it should turn into a stop button in case the user wants to end the animation early, and if the stop button is clicked, the 3d view will return to the state the user had it before they clicked the play button (so save which orbitals have been hidden by the user). Finally, add a playback-speed button to the top left of the 3d viewport to allow the user to toggle between animation speeds (options are 0.5x, 1x, 1.5x, 2x, 3x, default is 1x, when the button is clicked it cycles through the list of options).
